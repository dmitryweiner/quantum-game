# Quantum Game — план разработки

Веб-игра про «странности» квантового мира. Игрок — наблюдатель внутри
двумерного мира, и сам факт его взгляда меняет происходящее. Цель игры:
через игровые механики дать интуицию о суперпозиции, коллапсе, запутанности,
неопределённости, туннелировании и интерференции, не прибегая к формулам.

Статус документа: **v0.6** — M0–M4 и мультиязычность готовы, следующий этап M5.

## 1. Концепция

### 1.1. Главная механика — «взгляд наблюдателя»

- Игрок управляет персонажем-наблюдателем 👁️.
- У наблюдателя есть **поле зрения** — конус. Всё внутри конуса считается
  **измеряемым**.
- Квантовые объекты (частицы, кот, ключи, двери…) существуют в двух режимах:
  - **вне взгляда** — в суперпозиции: рисуются полупрозрачными «призраками»
    во всех возможных позициях/состояниях, со временем «расплываются»;
  - **во взгляде** — коллапсируют в одно состояние по правилу Борна
    (случайный выбор с вероятностью |амплитуда|²) и ведут себя классически.
- Отвёл взгляд — объект снова начинает «расплываться» из того места, где
  его видели в последний раз.
- У наблюдателя есть **очки** 🕶️ с переключаемым режимом (базис измерения
  Z / X) и регулируемой **шириной** конуса — это две «ручки», через которые
  в игру входят неопределённость и некоммутирующие измерения.
- В мире есть **другие наблюдатели**: камеры 📷, охранники 👀, «горячие» зоны
  🔥 — они тоже коллапсируют объекты (это и есть декогеренция). Игрок с ними
  не только борется, но и использует их.

Таким образом игрок не «толкает» предметы, а управляет тем, **когда, на что
и как смотреть**, чтобы вероятности сложились в его пользу.

### 1.2. Формат

- Короткие уровни (10–30 секунд на попытку, много попыток), сгруппированные
  в главы по эффектам.
- У каждого уровня есть цель («довести кота до двери», «зажечь обе лампы»,
  «не дать ядру распасться 30 секунд», «выиграть ≥ 80 % раундов»).
- После прохождения — короткое пояснение «What just happened?»
  (1–3 предложения, без формул).
- Режим **Sandbox** — свободно побродить среди квантовых объектов.

### 1.3. Графика

- 2D, вид сверху, сетка клеток. Все спрайты — эмодзи, отрисованные как текст
  (🐱 🧱 🔑 🚪 💡 ☢️ 🔴 🔵 ⚛️ 👁️ 🕶️ 📷 💣 🔥 ❄️ и т. п.).
- Суперпозиция — прозрачность (альфа ∝ вероятности) и лёгкое дрожание;
  коллапс — короткая вспышка + звук.
- Запутанность — пунктирная нить между партнёрами.
- Эмодзи рендерятся системным шрифтом; для единообразия на всех платформах
  подключаем CC0-шрифт **Noto Color Emoji** (лицензия OFL/CC0-совместимая,
  уточнить при подключении) или принимаем системный вид.

### 1.4. Принцип «парадокс как ключ»

Каждый уровень обязан удовлетворять трём условиям:

1. **Классическая стратегия проверяемо проигрывает.** Для каждого уровня в
   описании фиксируется, почему без квантового эффекта пройти нельзя:
   либо это невозможно вовсе (стена без двери — нужно туннелирование), либо
   порог недостижим (CHSH: классический максимум 75 %, порог уровня 80 %).
2. **Эффект сначала показывают, потом требуют.** Первый уровень главы —
   «демо» с подсказкой; дальше подсказки убираются.
3. **Есть объяснение после.** Экран «What just happened?» связывает
   решение игрока с настоящим физическим экспериментом.
4. **Есть справка по эффектам.** У каждого уровня в описании перечислены
   все квантовые эффекты, которые в нём встречаются (включая вспомогательные,
   например декогеренция от камеры на уровне про туннелирование). Для каждого
   эффекта — краткое описание в 1–3 предложения простым языком и ссылка на
   справочный источник (Википедия, учебная статья, видео). Справка доступна
   в игре по кнопке «ℹ️ Learn more» до начала уровня и на экране
   «What just happened?» после, а также открывается из меню выбора уровня.

Идея для усиления: в начале каждой главы — уровень **«Classical mode»**,
где квантовые правила отключены, и он заведомо непроходим. Игрок упирается,
после чего «включается» квантовый эффект и тот же уровень становится решаемым.

### 1.5. Структура описания уровня

Каждый уровень в `src/levels/` описывается объектом с обязательными полями:

```ts
interface LevelDef {
  id: string;                 // 'ch1-03'
  chapter: number;
  title: Text;                // { en: 'Cat at the Door', ru: '…' }
  goal: Text;                 // короткая цель для HUD
  hint?: Text;                // подсказка (только в демо-уровнях)
  whyClassicalFails: Text;    // текст для п. 1.4 (1): почему классически не пройти
  explanation: Text;          // «What just happened?» после прохождения
  effects: EffectId[];        // все эффекты, встречающиеся на уровне
  map: string[];              // ASCII-карта с эмодзи-объектами
  winCondition: WinCondition;
}
```

Справочник эффектов — один файл `src/strings/effects.ts`:

```ts
interface EffectInfo {
  id: EffectId;               // 'superposition', 'entanglement', 'chsh', …
  name: string;               // 'Quantum superposition'
  summary: string;            // 1–3 предложения простым языком
  links: { title: string; url: string }[];  // Википедия, статья, видео
}
```

Так один и тот же эффект описывается один раз, а уровень только ссылается на
него по `id`. Сборка в CI проверяет, что все `effects` уровня существуют в
справочнике и у каждого эффекта есть хотя бы одна ссылка.

## 2. Какие эффекты показываем

Приоритет: **P0** — обязательно для первого релиза, **P1** — следующий
релиз, **P2** — если останутся силы. Колонка «Почему без парадокса нельзя»
— требование п. 1.4.

### 2.1. Исходный набор

| # | Эффект | Игровая механика | Пример уровня | Почему без парадокса нельзя | Прио |
|---|--------|------------------|---------------|------------------------------|------|
| 1 | **Суперпозиция и коллапс (эффект наблюдателя)** | Объект вне взгляда «размазан» по клеткам; взгляд фиксирует одну по правилу Борна | Кот 🐱 в суперпозиции «слева/справа от стены». Нужно посмотреть на него в момент, когда вероятность быть у двери максимальна | Классически кот неподвижен и к двери не доходит | P0 |
| 2 | **Нелокальность / запутанность** | Пара 🔴🔵 с общим состоянием. Смотришь на ближний — дальний определяется сам | До дальнего ключа не дойти за отведённое время | P0 |
| 3 | **Неопределённость (Гейзенберг)** | Чем у́же конус (точнее «меряем» координату), тем сильнее разброс скорости после коллапса | Провести частицу через узкий проход: узкий взгляд даёт точную позицию, но непредсказуемую скорость; широкий — наоборот | Единственный способ «разогнать» частицу — сжать её позицию | P0 |
| 4 | **Туннелирование** | Вероятность оказаться по ту сторону стены 🧱 зависит от её толщины и «энергии» частицы | Пройти/протащить ключ сквозь стену без двери, не глядя на него | Двери нет | P1 |

### 4.1. Модель квантового объекта (упрощённая, но честная)

Полное решение уравнения Шрёдингера не нужно. Используем дискретную модель:

- `Superposition<S>` — массив ветвей `{ state: S, amp: Complex }`, нормированный.
  - `evolve(dt)` — «расплывание»: амплитуда перетекает в соседние клетки
    (дискретный шаг с фазой; тот же механизм даёт квантовое блуждание).
  - `measure(rng)` — выбор ветви с вероятностью `|amp|²`, схлопывание в неё.
- `Qubit` / `EntangledPair` — вектор состояния 1 или 2 кубитов.
  - Измерение в базисе Z или X (а для CHSH — под произвольным углом) ⇒
    проекция; у партнёра — условное состояние. Корреляции Белла и
    «забывание» при некоммутирующих измерениях получаются «бесплатно».
- Неопределённость (реализовано в M3): слайдер фокуса. Острый взгляд
  (узкий конус) — прежний коллапс каждый кадр. Размытый (широкий) — ловит
  ~2 фотона в секунду, каждый даёт гауссово измерение положения шириной до
  10 клеток, край поля зрения мягкий. Разброс импульса не задаётся формулой,
  а получается из волновой функции: узкий пакет разлетается, широкий —
  почти нет. Острый пинок / мягкое касание проверены плейтестом.
- Туннелирование (реализовано в M4): силовое поле — клетки решётки с
  потенциалом V = 4,5γ (выше края зоны 4γ, поэтому пройти можно только
  туннелированием). Формулы `exp(-2κd)` нет — затухание получается из
  волнового уравнения: поле в 1 клетку пропускает заметно, в 2–3 — почти
  ничего. Поле непрозрачно для взгляда (иначе взгляд «ловил» бы кота внутри
  поля и помогал ему пройти — измерение-индуцированное туннелирование).
- Зенон: «не распалось» эволюционирует как `cos²(ωt)`; наблюдение сбрасывает
  `t` в ноль с вероятностью выжить `cos²(ω·Δt)`.
- Интерференция: яркость на экране считается аналитически
  (`cos²(π·d·sinθ/λ)` × огибающая щели); флаг «щели наблюдаются» переключает
  на сумму двух одиночных распределений. Интерферометр для «бомбы» — те же
  две ветви с фазой: без препятствия детектор D никогда не срабатывает,
  с препятствием — в 25 % случаев.
- Измерение взглядом (реализовано в M1, `src/quantum/superposition.ts`):
  взгляд — проективное измерение «объект в видимой области?». «Да» —
  коллапс в одну из видимых клеток по правилу Борна; «нет» — амплитуда в
  видимых клетках обнуляется, остальное перенормируется (измерение с
  отрицательным результатом). Измерение повторяется каждый кадр, поэтому
  неотрывный взгляд работает как эффект Зенона: на просматриваемое место
  объект не попадает, а замеченный объект стоит на месте.
- Расплывание — непрерывное квантовое блуждание `i·dψ/dt = −γ·A·ψ`
  (A — матрица смежности свободных клеток), интегрируется RK4; проверено
  против точного решения через функции Бесселя.
- Проходимость уровней проверяется симуляцией в тестах (`tests/levels.test.ts`):
  с закрытыми глазами уровень не пройти, разумная стратегия выигрывает.
- Длинные уровни на портретном экране транспонируются (физика не меняется).
- Декогеренция: любой `Observer` (игрок, камера, зона) вызывает тот же
  `measure()`; разница только в том, кто и когда смотрит.
- Статистика: фермионы — запрет двойной занятости клетки при `evolve`;
  бозоны — усиление амплитуды перехода в занятую клетку (√(n+1)).

Все функции чистые, принимают `rng`, поэтому воспроизводимы в тестах.

### 4.2. Цикл кадра

1. `GazeSystem` вычисляет, какие объекты попали в конус игрока;
   `DecoherenceSystem` — в зоны действия камер/зон.
2. Для объектов **под наблюдением**: если были в суперпозиции — `measure()`,
   событие `collapsed` (вспышка, звук), дальше — классическая физика.
3. Для объектов **без наблюдения**: `evolve(dt)` — расплывание, проверка
   туннелирования у стен, тик распада.
4. Запутанные партнёры синхронизируются через общий `EntangledPair`.
5. `GhostRenderer` рисует ветви (альфа = вероятность), `HUD` — цель уровня.
6. `WinCondition` проверяет условие победы/поражения.

### 4.3. Управление (мобильное — основное)

| Действие | Телефон | Десктоп |
|----------|---------|---------|
| Движение | Виртуальный джойстик слева внизу (или тап по клетке — идти туда) | WASD / стрелки |
| Направление взгляда | Касание/перетаскивание в правой половине экрана: взгляд смотрит на точку касания | Курсор мыши |
| Ширина конуса | Слайдер справа (или щипок) | Колёсико мыши |
| Режим очков Z / X | Кнопка 🕶️ | Клавиша `Q` |
| «Закрыть глаза» (прекратить наблюдение) | Отпустить правую половину экрана | Правая кнопка мыши / `Space` |

- Phaser `Scale.FIT`, уровни строятся на сетке, которая умещается и в
  портрет (9:16), и в ландшафт (16:9); минимальная цель для тапа — 44 px.
- Все проверки производительности — на среднем Android-телефоне.
- Контролы проверяются на реальном устройстве на каждом этапе
  (через GitHub Pages — удобно, адрес всегда живой).

## 6. CI/CD (GitHub Actions)

- **`ci.yml`** — на `push` и `pull_request`:
  `npm ci` → `npm run lint` → `npm run typecheck` → `npm test` → `npm run build`.
  В `npm test` входит проверка уровней: все эффекты из `effects` есть в
  справочнике, у каждого эффекта есть описание и хотя бы одна ссылка.
- **`deploy.yml`** — на `push` в `main`:
  сборка Vite с `base: '/quantum-game/'` → `actions/upload-pages-artifact` →
  `actions/deploy-pages`. Адрес: `https://dmitryweiner.github.io/quantum-game/`.
  В настройках репозитория: Pages → Source → GitHub Actions.
- Защита `main` не используется (решение владельца репозитория).

## 7. Референсные проекты

На что смотрели, чтобы не изобретать велосипед и не повторяться:

- **Quantum Flytrap Virtual Lab / Quantum Game with Photons** — оптический
  стол в браузере: светоделители, поляризаторы, детекторы; есть бомба
  Элицура–Вайдмана и эффект Хонга–У–Манделя. Самая близкая по духу
  «честная» симуляция, но это конструктор, а не игра с персонажем.
- **Quantum Chess** — шахматы с суперпозицией фигур и коллапсом при
  «наблюдении» ходом противника. Хороший пример того, как число ветвей
  удваивается с каждым квантовым ходом — и почему нам нужно ограничивать
  количество ветвей на объект.
- **Quantum TiqTaqToe, Hello Quantum, Quantum Odyssey, Quantum Moves
  (ScienceAtHome), qCraft** — обучающие игры; по обзорам, из более чем 100
  квантовых игр лишь ~4 % реально образовательные, и почти все они про
  суперпозицию/запутанность. Декогеренция, Зенон, бомба, CHSH-игра в
  играх почти не встречаются — это наша ниша.
- **Игра CHSH** — стандартный пример «квантового преимущества»: 85 % против
  75 %. Классический предел доказан, что идеально подходит под принцип
  «без парадокса не пройти».
